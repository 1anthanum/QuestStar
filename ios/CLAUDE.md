# CLAUDE.md -- QuickTrack iOS/macOS Widget Project

## Project Identity

**QuickTrack** is a minimal iOS + macOS host app that serves as a carrier for WidgetKit widgets. It provides at-a-glance tracking for medication/supplements, QuestStar progress, and sleep -- all reading from existing backends (Supabase + HealthKit). No business logic lives in the app; it is purely a display + one-tap recording layer.

- **Parent project**: QuestStar (quest-tracker) -- gamified ADHD task management
- **Stack**: Swift 6, SwiftUI, WidgetKit, App Intents, SwiftData, HealthKit
- **Platforms**: iOS 17+ / macOS 14+ (multiplatform target)
- **Signing**: Free Apple ID (7-day re-sign, personal use only, no App Store)
- **Data sources**: Supabase REST API (existing tables) + HealthKit (sleep)

### Prerequisites
- Xcode 16+ (Swift 6, iOS 17 SDK)
- Free Apple ID signed in to Xcode
- App Group configured: `group.quicktrack.shared`

### Environment / Secrets
Secrets are stored in the host app's Settings view and persisted to App Group UserDefaults.

| Key | Purpose | Source |
|-----|---------|--------|
| `supabaseURL` | Supabase project URL | Same as web project's `VITE_SUPABASE_URL` |
| `supabaseAnonKey` | Supabase publishable key | Same as web project's `VITE_SUPABASE_ANON_KEY` |
| `supabaseUserToken` | Authenticated user JWT | Obtained via Supabase Auth (email/password login in Settings) |
| `supabaseUserId` | User UUID | Extracted from JWT or login response |

**IMPORTANT**: The widget reads these from App Group UserDefaults (`group.quicktrack.shared`). The host app writes them on login. No hardcoded keys in source code.

## Architecture

```
Host App (QuickTrack)
  |-- Settings: Supabase URL/key/login, HealthKit permissions
  |-- Tracker Registry: JSON config defining which trackers are active
  |-- App Intents: LogEventIntent, RefreshSummaryIntent
  |-- Writes config + cached data to App Group container
  |
Widget Extension (QuickTrackWidget)
  |-- TimelineProvider: reads from App Group cache, fetches fresh data
  |-- SmallWidgetView / MediumWidgetView / LargeWidgetView
  |-- Buttons trigger App Intents (iOS 17+)
  |
Shared (App Group container)
  |-- AppGroupManager: UserDefaults + file access for App Group
  |-- CacheManager: SwiftData store in App Group for offline display
  |-- Config: constants, App Group ID, Supabase config reader
```

### Data Flow

```
Supabase REST API ──> Host App / Widget TimelineProvider
                           |
                           v
                    TrackerDataSource protocol
                    |                        |
            SupabaseAdapter          HealthKitAdapter
                    |                        |
                    v                        v
             TrackerSummary (unified model)
                    |
                    v
              App Group Cache (SwiftData)
                    |
                    v
              Widget SwiftUI Views
```

### Key Design Decisions

1. **No custom backend**: All data comes from QuestStar's existing Supabase tables via PostgREST auto-generated API. Zero new server-side code.

2. **Adapter pattern over API gateway**: Data transformation (Supabase row -> TrackerSummary) happens in Swift, not in Edge Functions. Simpler, free-tier friendly, faster iteration.

3. **App Group is the bridge**: Widget extensions run in a separate process. All shared state (config, cache) must go through App Group (`group.quicktrack.shared`).

4. **Read-first, write-later**: v1 widgets are read-only (display data). Write-back (one-tap medication check) comes in Phase 3 via App Intents.

5. **Sync direction**: Widget writes -> Supabase -> QuestStar web pulls on next load. No real-time sync needed for personal use.

## v1 Trackers

### 1. Medication / Supplements (medication)

| Field | Value |
|-------|-------|
| Data source | Supabase `daily_habits.daily_checks` |
| Display | Unchecked items for today, completion ring |
| Action (v2) | Tap to check off -> POST to Supabase |
| Decision trigger | Unchecked = take medication NOW |

**Supabase query**:
```
GET /rest/v1/daily_habits?select=daily_checks,time_blocks&user_id=eq.{uuid}
Authorization: Bearer {jwt}
apikey: {anon_key}
```

**Data transform**: Extract today's date key from `daily_checks`, cross-reference with `time_blocks` activities to show unchecked items.

### 2. QuestStar Progress (queststar)

| Field | Value |
|-------|-------|
| Data source | Supabase `game_state` + `quests` |
| Display | XP, streak, next incomplete step |
| Action | None (opens QuestStar web) |
| Decision trigger | Streak about to break = do 1 step NOW |

**Supabase queries**:
```
GET /rest/v1/game_state?select=xp,streak,last_active_date&user_id=eq.{uuid}
GET /rest/v1/quests?select=id,name,steps&user_id=eq.{uuid}
```

**Data transform**: Calculate level from XP (reuse LEVELS thresholds), count incomplete steps, find most urgent quest (by deadline or staleness).

### 3. Sleep (sleep)

| Field | Value |
|-------|-------|
| Data source | HealthKit `HKCategoryTypeIdentifier.sleepAnalysis` |
| Display | Last night's sleep duration, 7-day average |
| Action | None (informational) |
| Decision trigger | < 6h = reduce task difficulty today |

**HealthKit query**: Query `sleepAnalysis` samples for the last 24h, filter for `asleepUnspecified` / `asleepCore` / `asleepDeep` / `asleepREM`, sum durations.

## Coding Conventions

### General
- **Swift 6** with strict concurrency checking
- **SwiftUI only** -- no UIKit unless absolutely necessary
- **Protocol-oriented**: `TrackerDataSource` protocol is the core abstraction
- **async/await** for all network + HealthKit calls
- **No third-party dependencies** for v1 (URLSession, not Alamofire; SwiftData, not Realm)

### Naming
- Types: `PascalCase` (Swift standard)
- Files: match primary type name (`TrackerSummary.swift`)
- App Group ID: `group.quicktrack.shared`
- UserDefaults keys: `quicktrack_` prefix (e.g., `quicktrack_supabaseURL`)
- SwiftData models: `Cached` prefix for cache-only models

### Widget Conventions
- All widgets must handle 3 states: `.loading`, `.error(message)`, `.loaded(summary)`
- TimelineProvider must return a fallback placeholder entry (never crash on missing data)
- Network requests in TimelineProvider must complete within 30 seconds
- Use `.systemSmall`, `.systemMedium`, `.systemLarge` family cases
- Widget refresh policy: `.atEnd` for time-sensitive data, `.after(date)` for hourly refresh

### Supabase REST Conventions
- Always include both `Authorization: Bearer {jwt}` and `apikey: {anon_key}` headers
- Use `Accept: application/vnd.pgrst.object+json` for single-row responses
- Handle 401 (token expired) by showing "Re-login required" in widget
- Handle network errors by showing cached data with "Last updated: {time}" label

### Error Handling
- Never crash in widget -- always show a meaningful fallback
- Log errors to `os.Logger` (category: "QuickTrack")
- Network errors: show cached data + staleness indicator
- Auth errors: show lock icon + "Open app to re-login"

## Supabase Integration Details

### Authentication Flow (Host App)
1. User enters email + password in SettingsView
2. Host app calls `POST {supabaseURL}/auth/v1/token?grant_type=password`
3. Response contains `access_token` (JWT) + `user.id` (UUID)
4. Store both in App Group UserDefaults
5. Widget reads these for authenticated REST queries

### REST API Pattern
```swift
// All Supabase REST calls follow this pattern:
func fetch<T: Decodable>(table: String, query: String) async throws -> T {
    let url = URL(string: "\(supabaseURL)/rest/v1/\(table)?\(query)")!
    var request = URLRequest(url: url)
    request.setValue("Bearer \(jwt)", forHTTPHeaderField: "Authorization")
    request.setValue(anonKey, forHTTPHeaderField: "apikey")
    request.setValue("application/json", forHTTPHeaderField: "Accept")
    let (data, _) = try await URLSession.shared.data(for: request)
    return try JSONDecoder().decode(T.self, from: data)
}
```

### QuestStar Data Mapping (Supabase -> Swift)

| Supabase Column | Swift Field | Notes |
|-----------------|-------------|-------|
| `game_state.xp` | `Int` | Use LEVELS array to calculate level |
| `game_state.streak` | `Int` | Display as "N-day streak" |
| `game_state.last_active_date` | `String` (ISO) | Compare with today for streak warning |

## Sync Considerations

### Widget -> Supabase -> QuestStar Web

When the widget writes to Supabase (Phase 3):
1. Widget's App Intent PATCHes `daily_habits.daily_checks` in Supabase
2. QuestStar web's `useCloudSync` pulls on next page load (login trigger)
3. Gap: web won't see changes until refresh/re-login

**v1 mitigation**: Acceptable for personal use. User opens QuestStar web rarely; widget is the primary interface for daily checks.

**Future option**: Add periodic pull to `useCloudSync` (every 5 min) or use Supabase Realtime subscription.

### QuestStar Web -> Supabase -> Widget

When QuestStar web writes (step completion, XP gain):
1. `useCloudSync` pushes to Supabase (2s debounce)
2. Widget's TimelineProvider fetches on next refresh cycle
3. Gap: widget may show stale data for up to 15-30 minutes (system-controlled refresh)

**v1 mitigation**: RefreshSummaryIntent allows manual refresh. Acceptable staleness for XP/streak display.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| Widget shows "Open app to configure" | App Group UserDefaults missing Supabase config | Open host app, go to Settings, enter credentials |
| Widget shows stale data | System refresh budget exhausted | Tap widget to open app, or use RefreshSummaryIntent |
| 401 from Supabase | JWT expired | Re-login in host app Settings |
| HealthKit data missing | Permission not granted | Open host app, re-request HealthKit authorization |
| Widget blank after install | App Group not configured in Xcode | Check Signing & Capabilities for both targets |
| "Re-sign required" alert | Free Apple ID 7-day expiry | Re-build from Xcode to refresh signature |

## Important Gotchas

1. **App Group is mandatory**: Widget and host app are separate processes. Without App Group, the widget cannot read any configuration or cached data. Both targets must have the same App Group capability.

2. **Widget memory limit**: ~30 MB. Keep network responses small. Only fetch needed columns (`select=xp,streak`, not `select=*`).

3. **Widget refresh is system-controlled**: You cannot force arbitrary refresh. `WidgetCenter.shared.reloadTimelines(ofKind:)` requests a refresh but the system may defer it.

4. **Free Apple ID limitations**: No push notifications, no CloudKit, no App Clips. Widgets and App Intents work fine. Must re-sign every 7 days.

5. **Supabase JWT expiry**: Default 1 hour. For widget use, consider increasing to 7 days in Supabase Dashboard > Auth > JWT expiry. Or implement token refresh in the host app.

6. **HealthKit on macOS**: Available on macOS 13+ but with limited data types. Sleep analysis works. Step count requires iPhone as source.

7. **SwiftData in App Group**: The SwiftData container must be explicitly configured to use the App Group URL, not the default app container.

8. **daily_checks format**: The JSONB field uses `{ "YYYY-MM-DD": { "actId": true } }`. Missing date key = nothing checked today. Missing actId = not checked.

9. **time_blocks null handling**: When `time_blocks` is null in Supabase, the widget should show generic defaults (water, exercise, breakfast, etc.) matching QuestStar's `DEFAULT_BLOCKS`.

10. **Quest data shape**: Supabase uses `quest_type` (snake_case), QuestStar JS uses `questType` (camelCase). Swift Codable with `CodingKeys` handles this mapping.
