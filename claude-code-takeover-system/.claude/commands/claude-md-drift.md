# /claude-md-drift

每月一次。检查项目中所有 CLAUDE.md 是否与实际代码一致。

**只输出报告，不直接修改 CLAUDE.md**（防止狐狸看鸡舍）。

## 流程

### 步骤一：找出所有 CLAUDE.md

```bash
find . -name "CLAUDE.md" -not -path "./node_modules/*" -not -path "./.git/*"
```

### 步骤二：逐个检查

对每个 CLAUDE.md，调用 `claude-md-keeper` 子代理（或直接执行下列检查）：

#### A. 「对外契约」段

- 段中列出的接口是否仍然存在？签名是否一致？（用 grep 验证）
- 是否有实际被外部引用的接口未被列出？

#### B. 「依赖」段

- "入"列出的调用方是否仍在调用？（用 grep）
- "出"列出的被调用方是否仍被调用？
- 是否有新的调用关系未被记录？

#### C. 「内部实现」段

- 描述是否与实际代码主体方向一致？
- 是否有明显已过时的描述？

#### D. 「替换难度自评」段

- 用 grep 重新计算"影响其他文件数"，与文档中的 N 比较
- 若偏差 > 50%，建议更新

#### E. 「相关 ADR」段

- 链接是否还有效？
- 是否有新增的 ADR 未被链接？

#### F. 子目录地图（仅根 CLAUDE.md）

- 是否有新建子目录未被记录？
- 是否有已删除子目录仍被列出？

### 步骤三：输出报告

将报告写入 `docs/health-check/claude-md-drift-YYYY-MM-DD.md`：

```markdown
# CLAUDE.md 漂移检查报告 - YYYY-MM-DD

## 总览

- 检查的 CLAUDE.md 数量：N
- 发现漂移项：M
- 建议立即修复：K
- 可推迟：L

## 详细漂移项

### <文件路径>

#### 漂移项 1
- 类型：A / B / C / D / E / F
- 当前描述：…
- 实际情况：…
- 建议：…

…
```

## 完成后

给用户中文总结：

- 整体漂移程度（轻 / 中 / 重）
- **本月最严重的 1-2 项漂移**
- 推荐用户**按报告顺序逐条审阅**，决定哪些更新文档、哪些需要先回滚代码再说

**严禁**让 AI 一次性自动修复全部漂移。
