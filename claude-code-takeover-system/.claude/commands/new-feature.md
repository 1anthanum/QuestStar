# /new-feature

用户要新增一个功能。在写任何代码之前，**必须**完整回答以下七个问题。

任一问题答不上来，停下来与用户讨论。

## 七题门禁

### 1. 上下文确认

读项目根 `CLAUDE.md` + 与本功能可能相关的所有子目录 `CLAUDE.md`。

报告「已读 X、Y、Z」。

### 2. 行为规格新增

在 `BEHAVIOR_SPEC.md` 中，这个新功能会以哪些「当用户做 X，系统应该 Y」的形式新增条目？

请先**草拟出来给用户看**，不要直接写入文件。

### 3. 改动范围

实现这个功能需要修改哪些文件？需要新增模块吗？

为每个文件 / 模块用一句话说明改动性质（新增 / 修改 / 删除 / 重构）。

### 4. 契约 vs 实现

对每个会被改动的模块，告诉用户：

- 本次改动是修改该模块的「对外契约」，还是只改「内部实现」？
- 哪些调用方会被波及？
- 涉及哪些 CLAUDE.md 需要更新？

### 5. 冲突检查

这个功能会不会与现有的任何 BEHAVIOR_SPEC 规则冲突？
与现有 CLAUDE.md「对外契约」是否冲突？

如果会，列出冲突项；用户决定是修改规则还是放弃功能。

### 6. 实现路径取舍

实现路径有几种？分别的取舍是什么？推荐哪种？

**重点说明**：哪种路径的「替换难度自评」最低？（即未来最容易重写）

### 7. 规模估算

- 会涉及多少行代码？
- 需要新增哪些第三方依赖？
- 需要新增 / 更新哪些 CLAUDE.md？
- 预计需要多少个 commit？

## 完成后

**回答完七点停下**，等用户说「按方案 X 实现」再开始。

如果用户决定实现，进入下一步：

- 若涉及新增模块 → 提示运行 `/new-module`
- 若仅在现有模块中添加 → 按 `/refactor` 的六步流程实现
