## 工作约定（会话宪法，严格遵守）

1. 默认只读。任何会修改文件的操作，必须先在对话里说明你要改什么、为什么，等用户说「可以」再动手。
2. 不确定的事必须说「不确定」。禁止猜测后输出确定语气。
3. 单次改动 ≤ 30 行 diff。若必须超过，先停下来征求同意。
4. 不要顺手做任务以外的事：不顺手清理代码、不顺手升级依赖、不顺手重命名。
5. Python 代码必须用我能读懂的风格：避免装饰器叠装饰器、避免元类、避免动态 import、避免 monkey-patching。
6. 前端代码用户无法阅读。任何前端改动必须配套一个端到端行为测试，测试名称用中文描述用户行为。
7. 引入新的第三方依赖、新的网络调用、新的文件读写、新的权限请求之前，必须先告诉用户并征求同意。
8. 每次工作完成后，用中文一段话总结：改了什么、为什么、对用户有什么可见影响、可能的副作用。
9. 用户让你做 A 但你认为应该做 B，请先把 B 的理由说出来等用户决定，不要擅自换方向。
10. 所有面向用户的解释禁止使用未解释过的术语；必须用术语时立刻用一句中文解释。
11. 修改任何代码前，必须先读：
    a) 项目根目录的 CLAUDE.md（本文件）
    b) 涉及目录的 CLAUDE.md（若存在）
    c) 涉及目录的所有父目录的 CLAUDE.md（若存在）
    读完用一句话告诉用户「已经读过 X、Y、Z」，再开始动手。
12. 任何改动完成后必须同步更新涉及目录的 CLAUDE.md。
    - 若改动改变了「对外契约」段中的接口：必须同时更新调用方目录的 CLAUDE.md 和 BEHAVIOR_SPEC.md
    - 若只改动了「内部实现」段所述细节：只更新本目录 CLAUDE.md 的内部实现描述即可
    - **不更新 CLAUDE.md = 改动不算完成**，会被 Git pre-commit hook 拦截

## 设计哲学

本项目遵循"**易于改变，而非永不改变**"原则：

- 接口越窄越好
- 信息隐藏（Parnas, 1972）：每个模块藏一个未来可能改变的决策
- 先重复三次再抽象
- 任何模块的"替换难度"目标：< 5 个其他文件受波及
